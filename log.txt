2026-08-13 - Backtesting environment and T5YIE scenario design
Idea:
- Separate faithful use of the raw T5YIE observation from noise reduction using the mean of the latest three genuine FRED observations.
- Test availability conservatively with 0, 1, and 2 trading-day lags instead of selecting one assumption in advance.
- Remove the close-to-close look-ahead by computing the signal at month-end close and executing at the following trading-day close.

Implementation:
- Created a project-local .venv and installed numpy, pandas, yfinance, matplotlib, plotly, and streamlit.
- Added t5yie_scenarios.py. It writes experiment artifacts under results/ and does not overwrite the existing SQLite backtest result tables.
- Defined six scenarios: A0/A1/A2 use raw T5YIE with 0/1/2-day lag; M0/M1/M2 use a three-observation mean with 0/1/2-day lag.
- The three-observation mean is calculated before reindexing/forward-filling, so holidays do not count the same FRED value multiple times.
- Added gross and 5/10/30bp cost cases, three subperiods, and SPY/static-allocation benchmarks.

Validation before experiment:
- Reproduced the legacy stored result exactly: gross CAGR 23.6085%, gross MDD -23.6931%, 30bp net CAGR 21.3488%, and SPY CAGR 11.8539%.

Result:
- All six scenarios completed successfully over the common tradable sample. No existing database result table was overwritten.
- Correcting execution from an impossible same-close trade to next-trading-day close reduced A0 gross CAGR from 23.61% to 21.95% (about 1.66 percentage points per year).
- At 10bp one-way cost, full-period results were:
  A0 21.21% CAGR / 1.087 Sharpe / -24.05% MDD;
  A1 19.89% / 1.029 / -24.05%;
  A2 19.98% / 1.038 / -24.05%;
  M0 20.89% / 1.072 / -24.05%;
  M1 19.98% / 1.034 / -24.05%;
  M2 20.41% / 1.055 / -24.05%.
- Three-observation smoothing alone (M0) changed only 2 of 280 comparable monthly positions versus A0 and slightly reduced CAGR. It did not reduce maximum drawdown.
- A1 and M1 were effectively tied on CAGR (19.89% vs 19.98%). M1 had a marginally higher Sharpe but underperformed A1 in 2003-2012 and was nearly identical thereafter.
- A0 beat SPY and both static allocation benchmarks by a wide margin. Benchmark CAGRs were SPY 11.60%, static regime mix 11.87%, and five-asset equal weight 10.93%.
- Conclusion: keep A0 as the faithful research specification and A1 as the conservative availability specification. Do not promote the three-observation mean to the main model because it did not deliver a consistent robustness or drawdown benefit. Retain M1 as a sensitivity check.
- Reproducible output files are generated under the ignored `results/` directory.

2026-08-13 - ALFRED point-in-time vintage audit
Idea:
- Determine whether the strong A0 result uses T5YIE observations that were subsequently revised, and measure any resulting level, momentum, position, CAGR, or drawdown differences.

Implementation:
- Added alfred_vintage_backtest.py and downloaded 152 month-end ALFRED snapshots.
- Compared each month-end snapshot with the current FRED history on the same observation date.
- Separately tracked whether the exact month-end observation was already present in the month-end snapshot. This separates data revision from publication/availability timing.
- Re-ran both the point-in-time and latest-history models from the common 2014-02-03 start using signal-at-month-end and next-trading-day-close execution.

Data-history finding:
- ALFRED reports 2014-01-27 as the first release date of T5YIE. Values dated back to 2003 were released retrospectively, so a strict real-time T5YIE backtest cannot begin in 2003.

Revision audit result (2014-01 through 2026-08):
- Audited month ends: 152.
- Same-observation T5YIE revisions: 0.
- Exact month-end value revisions: 0.
- Revisions crossing the 2.0% threshold: 0.
- Revisions changing 60-trading-day momentum: 0.
- Revisions changing the final position: 0.

Availability-timing result (not a revision):
- The exact same-day month-end observation was not yet present in 66 of 152 month-end snapshots.
- Using the latest observation actually present at month-end changed the 2.0% level test in 3 months, the 60-day momentum test in 2 months, and the final position in 2 months (2014-06-30 and 2018-05-31).
- At 10bp, ALFRED month-end-available CAGR was 21.34% versus 21.83% using today's finalized history over the same 2014-2026 sample. Both had -23.40% MDD.
- The performance difference is therefore about 0.49 percentage points of CAGR and is attributable to same-day availability, not historical revisions.

Conclusion:
- No point-in-time revision bias was found after T5YIE's first release. If the model convention permits the month-end observation to be used for a next-day-close trade, A0 remains the preferred specification.
- The 2003-2013 result must still be labeled reconstructed/backfilled because T5YIE was not published until 2014-01-27.
- Reproducible output files are generated under the ignored `results/` directory.

2026-08-13 - Local Mac live-testing pipeline
Idea:
- Run a small-account operational test without automated brokerage integration.
- Do not depend on the Mac being awake at 07:30. Run at login and every two hours while awake; every run re-fetches recent history and fills dates after the last stored observation.
- Separate frozen point-in-time signals, a fractional-share Shadow portfolio, an actual manually entered portfolio, and an SPY benchmark.

Implementation:
- Added live_core.py with an additive SQLite schema for settings, run history, immutable signal snapshots, manual trades, daily NAV, and data issues.
- Added daily_job.py. It incrementally re-fetches the latest market window and FRED series, validates the latest row, freezes previously unseen daily/month-end signals, rebuilds Shadow/SPY/live NAV, and records SUCCESS or FAILED status.
- Shadow execution uses the next NYSE session close and 10bp default one-way cost. XLP+IEF is bought 50/50 at entry and then allowed to drift until the next monthly rebalance; it is not reset daily.
- Added a Streamlit `실전 테스트` page for start capital/date/cost setup, current and frozen signals, Shadow/live/SPY visualization, run history, and manual trade entry.
- Added launch_daily.sh with a filesystem lock and a launchd configuration using RunAtLoad plus a two-hour StartInterval.
- Added install_launchd.sh, uninstall_launchd.sh, requirements.txt, consolidated README operating instructions, and daily rolling SQLite backup retention.

Validation:
- Black-box test with an isolated temporary SQLite database and synthetic NYSE sessions verified initial execution, catch-up calculation, month-end signals, Shadow/SPY NAV, manual BUY entry, live NAV, repeat-run idempotency, and safe failure on an incomplete latest price row.
- Result: 2 pytest black-box tests passed.
- launchd plist passed `plutil -lint`.
- All new Python modules passed compilation.
- Streamlit live page passed AppTest with zero exceptions, and the full app returned healthy HTTP 200 responses.
- Existing production DB dry run succeeded without overwriting legacy backtest tables.
- Real network catch-up succeeded: prices and T5YIE advanced from 2026-08-07 to 2026-08-12, and two live job runs were recorded as SUCCESS.

Operational status:
- Automatic launchd registration was intentionally not activated during implementation. The user should first save live start date and capital in the dashboard, then run `./install_launchd.sh` once.
- No real trade was created, and no existing backtest result table was replaced.
