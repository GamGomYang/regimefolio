# API 연결 전 비밀정보 보호 점검

점검일: 2026-10-28. 실제 계좌 연결이나 주문 없이 로컬에서 검사했다.

## 적용 사항

- `.gitignore`: 환경 파일, 개인키/인증서, 자격증명 파일, 계좌 증빙 JSON의 지정 파일명과 디렉터리, 임의 위치의 SQLite DB/백업, HAR를 제외한다. 임의 이름의 계좌 JSON은 자동으로 보호되지 않으므로 `data/statements/` 등 제외된 경로에 보관한다.
- `.env.example`: 값이 없는 변수 이름만 공유한다. 환경 파일을 자동 로드하는 기능은 없다.
- `broker/security.py`: 외부로 출력할 오류는 검토된 고정 코드만 허용한다. 임의 예외 메시지는 일반 오류 코드로 대체한다. 주문/원장/조회 DB와 엔진 백업에 소유자 전용 권한 `0600`을 적용하고 최종 경로의 심볼릭 링크를 거절한다. 상위 경로는 신뢰할 수 있는 사용자 소유 디렉터리를 사용해야 한다.
- CLI와 WebSocket 오류 처리에 공개 오류 코드 필터를 적용한다. HTTP 응답 본문이나 인증 헤더를 디버그 출력에 추가하지 않는다.
- `scripts/check_secrets.py`: 작업 파일, Git 인덱스, 도달 가능한 Git 이력에 대한 오프라인 패턴 검사. 출력은 파일명/행/규칙만 포함하고 탐지 값은 출력하지 않는다.
- `.githooks/pre-commit`: 인덱스 내용 검사를 수행한다. 기존 훅이 없는 현재 저장소에 `core.hooksPath=.githooks`를 설정했다. 신규 clone에서는 아래 명령으로 별도 활성화해야 한다.

```sh
git config --local core.hooksPath .githooks
python3 scripts/check_secrets.py
python3 scripts/check_secrets.py --staged
python3 scripts/check_secrets.py --history
```

## 적용 범위와 운영 규칙

패턴 검사 결과는 비밀정보 부재를 보증하지 않는다. 알려지지 않은 키 형식, 인코딩된 값, 패턴과 무관한 계좌정보는 탐지되지 않을 수 있다. 무시된 로컬 파일의 내용, 원격 저장소의 별도 참조, 삭제된 Git 객체, 외부 로그/CI 설정은 이번 내용 검사 대상이 아니다.

`.gitignore`는 이미 추적 중인 파일이나 과거 커밋을 제거하지 않는다. `git add -f`로 포함한 민감 파일은 훅의 파일명/내용 검사로 일부 차단하지만, 훅은 `--no-verify`로 우회할 수 있다. 원격 강제 차단이 필요하면 같은 검사를 CI/저장소 정책에도 연결해야 한다. 이번 작업에는 원격 CI 변경이 포함되지 않는다.

실제 키는 소스/커밋 메시지/명령행 인수에 작성하지 않고 로컬 환경변수 또는 자격증명 저장소로 주입한다. 로컬 비밀 파일은 `0600`으로 관리한다. 실제 키가 이미 외부에 노출되었다면 파일 삭제만으로 해결되지 않으며 해당 키 폐기/재발급이 우선이다. 이번 검사에서 회전이 필요한 실제 키는 발견되지 않았다.
